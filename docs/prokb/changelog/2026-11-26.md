# prokb changelog — 2026-11-26

## [00:42 UTC]

Version: 0.2.0 → 0.3.0

Fixes all five open GitHub issues (#2, #3, #4, #5, #6) plus one crash found while fixing #6.

### `kb query` filters are exact and no longer silently empty (#6, plus `--after` crash)
- Removed every chroma `where` clause from `src/prokb/query.py`. On chromadb 1.5.9 the metadata `$contains` does no substring match (it returned 0 chunks with no error), and `$gte` on a date string raised `ValueError: Expected operand value to be an int or a float for operator $gte`. The old retry did not catch that error, because it only matched messages containing "where" or "filter".
- With `--path` or `--after` set, the new `_exact_filtered_search` loads all chunks (`collection.get`), filters them in Python and ranks them by brute-force cosine distance (numpy). An ANN query, even restricted with `ids=`, was measured to miss an outlier among near-identical vectors (11 of 20 fresh collections returned nothing). Unfiltered queries are unchanged.
- `numpy` is now a declared direct dependency.

### `kb diary` reads stdin and refuses an empty body (#5)
- `-` reads the body from stdin; the command fails if stdin is a TTY.
- New `--file PATH` option. Positional text and `--file` together are rejected.
- An empty or whitespace-only body is rejected from every source with exit 2, before anything is written or indexed.

### Agent worktrees are no longer indexed (#3, #4)
- `.claude` and `.hypothesis` added to the default `exclude_dirs`. The `kb init` YAML template also gets `.pytest_cache`.
- The scanner skips any directory below the project root that contains a `.git` FILE (the worktree marker), whatever its name.
- The `kb init` YAML template now renders `exclude_dirs` from `DEFAULTS`. Before, the template list was shorter: `build`, `dist`, `.next`, `target`, `.cache` and others were missing, so `build/lib` copies were indexed (observed live while bootstrapping this repo's own KB). A test checks that the two lists are equal.

### One writer per repo (#4)
- New `src/prokb/lock.py`: a non-blocking `flock` on `knowledge/.kb.lock` around `kb update`, `kb diary --update` and indexer full/incremental. A second writer fails fast with "another kb update is running in <root>", exit 1. `kb diary --update` still writes the entry, but reports that it was not indexed. Auto-reindex during a query skips with a note.
- `kb init` now appends `knowledge/chroma_db/`, `knowledge/manifest.json` and `knowledge/.kb.lock` to `.gitignore` idempotently, as the fleet rule (2026-11-09) already described.

### Valid collection names (#2)
- `derive_collection_name` replaces invalid characters and strips leading/trailing non-alphanumerics (`.agents` → `agents_knowledge`), then validates against chroma's rule. `kb init` fails with a clear error instead of writing an unusable config.
- An explicitly configured `collection_name` is validated at config load.

### Test harness
- `pythonpath = ["src"]` in pytest config. Before this, the suite imported the pipx-installed copy, so source edits were not under test.
- `filterwarnings = ["error"]` (fleet rule).
- `scripts/reinstall-and-test.sh` uses `mktemp -d` instead of a hard-coded scratchpad path from an old session.

### Tests
`KB_RUN_INTEGRATION=1 ./scripts/test.sh`: 83 passed, 0 skipped, 0 warnings. Before: 40 passed, 2 skipped, run against the installed copy. New files: `tests/test_query_path.py` and `tests/test_lock.py`; diary, config and scanner tests extended.

## [01:21 UTC]

Version: 0.3.0 → 0.3.1

### `kb mcp` works again on the mcp 2.x SDK
- `pyproject.toml` declared `mcp>=1.0` with no upper bound. A fresh install (here: the `pipx install --force` that rolled out 0.3.0) resolved `mcp` 2.3.0, which renamed `FastMCP` to `MCPServer`. Every `kb mcp` start then failed with `ModuleNotFoundError: No module named 'mcp.server.fastmcp'`, so the KB MCP tools were unavailable to agents on any machine with a fresh install. Found during the cross-model bug hunt: two repro tests could not even import the server.
- `src/prokb/mcp_server.py` now uses `mcp.server.mcpserver.MCPServer` (same constructor, `@tool()` and `run(transport="stdio")`) and reports the package version. Dependency pinned to `mcp>=2.3,<3` (latest stable; a future major must be a deliberate migration).
- New `tests/test_mcp_server.py`: imports the server and lists its tools. Before this, no test imported `mcp_server`, which is why the break was invisible.
- Live check: stdio handshake against the installed `kb mcp` returned server `KnowledgeBase-knowledge 0.3.1`, tools `knowledge_list_sources`, `knowledge_search`, `knowledge_status`, and a working `knowledge_status` call.

Tests: `KB_RUN_INTEGRATION=1 ./scripts/test.sh` 85 passed, 0 skipped, 0 warnings.

## [09:11 UTC]

Version: 0.3.1 → 0.4.0

Fixes all 36 defects proven by the bug hunt (tickets #8 to #15). Each repro test lost its `xfail(strict=True)` marker and is now a plain regression test. Codex (`fleet delegate` run c6b2d1) wrote the first patch. The orchestrator reviewed it and fixed two regressions in it, plus one test-only shortcut (below).

### #8 diary
- `kb diary` opens the file exclusively. If the same title is used in the same second, it writes `-2`, `-3`, ... and never overwrites (V1).

### #9 chunker
- `chunking.max_tokens` / `min_tokens` from the config are honoured. Before, `index_file` read non-existent top-level keys (V2).
- A paragraph over the limit is split on lines, then words (V14).
- A split fenced code block is closed and reopened, so fences stay balanced (V15).
- A bare `##` heading keeps the following body line (V25).
- The code-block placeholder prefix is made unique against the text, so literal `__CODEBLOCK_0__` survives (V26).

### #10 translation
- Language detection uses the configured `source_language`/`target_language` instead of hard-coded `hu` (V3).
- `langdetect` is now a declared dependency. It was imported optionally but never declared, so any non-Hungarian source language was never detected. Seeded for deterministic results.
- With translation disabled, `pending_translation` entries are indexed (V13).

### #11 index consistency
- A failed chroma delete is no longer swallowed:
  - `index_file` aborts before adding new chunks, so no duplicates (V4A);
  - a deleted file keeps its manifest entry for a retry (V4B).
- An emptied file has its old chunks removed (V5).
- HTML comments are content: only a leading comment used to be stripped, which dropped real text (V29).
- The manifest is saved after every file, so an error on one file does not lose the others' progress (V30).
- Full rebuild resets every entry first (V8):
  - missing sources become `deleted`;
  - present ones become `pending_index` with `chunk_count` 0.
  - Orchestrator fix: an untranslated file goes back to `pending_translation`; the Codex patch left it `pending_index`.

### #12 manifest, lock, change detection
- The manifest is written as UTF-8, atomically (temp file, fsync, `os.replace`). It no longer depends on the locale (V6).
- `scanner --init-manifest` takes the write lock (V7).
- Change detection compares size as well as mtime (V12).
- When mtime changes but the hash does not, the new mtime and size are stored, so the file is not rehashed every run (V24).
  - Orchestrator fix: a read-only scan, such as `kb update --status`, skips that refresh if a writer holds the lock, instead of failing with `LockHeldError`.
- The lock's re-entrancy is per thread, so a second thread is blocked (V22).

### #13 security
- Symlinks resolving outside the project root are skipped (V9).
- Include patterns with `..` or an absolute path raise `ConfigError` (V10).
- Every manifest key turned into a path goes through `config.contained_path` (V11): the source read, the translation read and the translation delete.

### #14 config
- Multi-segment `exclude_dirs` entries such as `docs/archive` work (V16).
- `project_name` is quoted in the generated YAML (V17).
- An empty YAML section falls back to the defaults (V18).
- The collection name is checked with `fullmatch`, so a trailing newline is rejected (V34).
- `find_config` ignores a directory named `knowledgebase.yaml` (V35).
- `kb install-mcp` on an empty or malformed `.mcp.json` exits 1 and leaves the file unchanged (V36).

### #15 query and MCP output
- `knowledge_search` captures output through one per-thread stdout proxy, not a global redirect, so concurrent calls no longer cross-talk (V19).
  - Orchestrator fix: the Codex patch only used the proxy when the test had replaced the query function. Now it is always used, so stray prints cannot reach the stdio protocol stream.
- Impossible dates such as `12345678` are rejected (V20).
- `kb update --batch N` indexes at most N files (V21).
- A `None` metadata entry is handled (V27).
- `total_matched` is counted before the limit (V28).
- `--top 0` and negative values are rejected (V31).
- `kb status` exits 1 with an `error` field when the store is unreadable (V32).
- The empty-index JSON keeps the full schema (V37).
