# prokb changelog — 2026-11-26

## [00:42 UTC]

Version: 0.2.0 → 0.3.0

Fixes all five open GitHub issues (#2, #3, #4, #5, #6) plus one crash found while fixing #6.

### `kb query` filters are exact and no longer silently empty (#6, plus `--after` crash)
- Removed every chroma `where` clause from `src/prokb/query.py`. On chromadb 1.5.9 the metadata `$contains` does no substring match (it returned 0 chunks with no error), and `$gte` on a date string raised `ValueError: Expected operand value to be an int or a float for operator $gte`. The old retry did not catch that error, because it only matched messages containing "where" or "filter".
- With `--path` or `--after` set, the new `_exact_filtered_search` loads all chunks (`collection.get`), filters them in Python and ranks them by brute-force cosine distance (numpy). An ANN query, even restricted with `ids=`, was measured to miss an outlier among near-identical vectors (11 of 20 fresh collections returned nothing). Unfiltered queries are unchanged.
- `numpy` is now a declared direct dependency.

### `kb diary` reads stdin and refuses an empty body (#5)
- `-` reads the body from stdin; the command fails if stdin is a TTY.
- New `--file PATH` option. Positional text and `--file` together are rejected.
- An empty or whitespace-only body is rejected from every source with exit 2, before anything is written or indexed.

### Agent worktrees are no longer indexed (#3, #4)
- `.claude` and `.hypothesis` added to the default `exclude_dirs`. The `kb init` YAML template also gets `.pytest_cache`.
- The scanner skips any directory below the project root that contains a `.git` FILE (the worktree marker), whatever its name.
- The `kb init` YAML template now renders `exclude_dirs` from `DEFAULTS`. Before, the template list was shorter: `build`, `dist`, `.next`, `target`, `.cache` and others were missing, so `build/lib` copies were indexed (observed live while bootstrapping this repo's own KB). A test checks that the two lists are equal.

### One writer per repo (#4)
- New `src/prokb/lock.py`: a non-blocking `flock` on `knowledge/.kb.lock` around `kb update`, `kb diary --update` and indexer full/incremental. A second writer fails fast with "another kb update is running in <root>", exit 1. `kb diary --update` still writes the entry, but reports that it was not indexed. Auto-reindex during a query skips with a note.
- `kb init` now appends `knowledge/chroma_db/`, `knowledge/manifest.json` and `knowledge/.kb.lock` to `.gitignore` idempotently, as the fleet rule (2026-11-09) already described.

### Valid collection names (#2)
- `derive_collection_name` replaces invalid characters and strips leading/trailing non-alphanumerics (`.agents` → `agents_knowledge`), then validates against chroma's rule. `kb init` fails with a clear error instead of writing an unusable config.
- An explicitly configured `collection_name` is validated at config load.

### Test harness
- `pythonpath = ["src"]` in pytest config. Before this, the suite imported the pipx-installed copy, so source edits were not under test.
- `filterwarnings = ["error"]` (fleet rule).
- `scripts/reinstall-and-test.sh` uses `mktemp -d` instead of a hard-coded scratchpad path from an old session.

### Tests
`KB_RUN_INTEGRATION=1 ./scripts/test.sh`: 83 passed, 0 skipped, 0 warnings. Before: 40 passed, 2 skipped, run against the installed copy. New files: `tests/test_query_path.py` and `tests/test_lock.py`; diary, config and scanner tests extended.
