prokb 0.2.0 -> 0.3.0: fixed all five open GitHub issues (#2-#6) plus a --after crash. (1) What changed: kb query path/date filters no longer use chroma where-clauses; filtered queries load all chunks, filter in Python and rank by exact brute-force cosine (numpy). kb diary accepts - (stdin) and --file, and rejects empty bodies. .claude/.hypothesis excluded by default and any dir holding a .git FILE (worktree) is skipped. A per-repo flock (knowledge/.kb.lock) guards every index writer. kb init derives a valid collection name (.agents -> agents_knowledge) and appends the generated-index lines to .gitignore. pytest now imports src/ (before, the suite silently tested the pipx-installed copy) and runs with filterwarnings=error. (2) Why: on chromadb 1.5.9 metadata $contains silently matched nothing and $gte on date strings raised ValueError; HNSW, even with ids= restriction, missed an outlier among identical vectors in 11 of 20 fresh collections, so only an exact scan is reliable for filtered search. Agent worktrees doubled indexes, concurrent writers corrupted HNSW, and kb diary - wrote a literal dash. (3) Not changed: unfiltered query path (still ANN), embedding models, index format; existing repos keep their knowledgebase.yaml (worktree skip and lock apply automatically, the .claude exclude only via new init or manual edit). (4) Impact: every fleet repo using kb gets correct --path/--after results, safe stdin diary entries and no worktree duplicates after pipx reinstall. Tests: 83 passed, 0 skipped, 0 warnings.
